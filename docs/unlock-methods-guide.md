# 数据库解锁方式使用说明

KeePassHO 支持多种数据库解锁（认证）方式，在解锁页面的「认证方式」下拉框中选择。各方式与 KeePass 桌面版 / KeePassXC 保持兼容。

## 支持方式总览

| 认证方式 | 兼容来源 | 前置条件 |
|---|---|---|
| 仅密码 | KeePass / KeePassXC 通用 | — |
| 仅密钥文件 | KeePass / KeePassXC 通用 | 密钥文件（.keyx / .key） |
| 密码 + 密钥文件 | KeePass / KeePassXC 通用 | 密钥文件 |
| 密码 + 一次性密码（恢复模式） | KeePass + OtpKeyProv 插件 | 辅助文件 `.otp.xml` |
| 密码 + 一次性密码 | KeePass + OtpKeyProv 插件 | 辅助文件 `.otp.xml` + 令牌（HOTP） |
| 密码 + 挑战-应答（Keepass XC） | KeePassXC + YubiKey | YubiKey（NFC）+ KDBX 4 |
| 密码 + 密钥文件 + 挑战应答（Keepass XC） | KeePassXC + YubiKey | 密钥文件 + YubiKey（NFC）+ KDBX 4 |

## 通用操作流程

1. 打开/选择 `.kdbx` 数据库文件（本地、WebDAV、S3、OneDrive 等存储均支持）；
2. 在「认证方式」下拉框中选择与建库时一致的认证方式（最近记录会自动记忆上次的方式）；
3. 输入各认证分量，点击「解锁」。

> 生物识别（指纹/面容）开启后，解锁页会自动代填**已保存的密码分量**；OTP 码、YubiKey 贴卡等硬件因子仍需手动完成（出于安全设计，不自动提交）。

## 各方式操作指引

### 1. 仅密码 / 仅密钥文件 / 密码 + 密钥文件

- 与 KeePass 桌面版行为一致；
- 密钥文件支持从文件选择器选取（本地存储），选择后记忆在最近记录中。

### 2. 密码 + 一次性密码（OtpKeyProv）

**前置**：在 KeePass 桌面版安装 OtpKeyProv 插件，为数据库创建一次性密码保护，生成辅助文件 `<数据库名>.otp.xml`（与数据库放在同一目录）。

**步骤**：

1. 选择认证方式「密码 + 一次性密码」；
2. 应用自动定位并读取同目录辅助文件（远端存储同样支持）；定位失败时点击「选择辅助文件」手动指定（选择位置会被记忆，下次免选）；
3. 输入主密码 + 令牌上的 `OtpsRequired` 个 OTP 码（HOTP，按顺序）；
4. 点击「解锁」。

**Counter 写回**：解锁成功后应用自动把辅助文件中的 Counter 前移（`Counter += OtpsRequired`）并重新加密写回；远端只读时仅告警不阻断。

**恢复模式（令牌丢失）**：选择「密码 + 一次性密码（恢复模式）」，直接输入建库时保存的恢复密钥（支持 Hex / Base64 / Base32 / UTF-8 / Dec 编码），无需令牌。恢复模式不写回 Counter。

### 3. 密码 + 挑战-应答（Keepass XC + YubiKey NFC）

**前置**：

- YubiKey 5 系列（NFC），在 KeePassXC 中为数据库配置「Challenge-Response」挑战-应答，记住所选 **HMAC 槽位**（Slot 1 = 短按 / Slot 2 = 长按）；
- 数据库须为 **KDBX 4** 格式（KDBX 3 不支持，解锁时会明确提示）。

**步骤**：

1. 选择认证方式「密码 + 挑战-应答（Keepass XC）」（含密钥文件时选「密码 + 密钥文件 + 挑战应答」）；
2. 在「YubiKey 挑战槽位」下拉框选择与 KeePassXC 中一致的槽位（默认槽位 2；槽位选择会被记忆）；
3. 输入主密码，点击「解锁」；
4. 弹出「触碰 YubiKey」引导后，将 YubiKey 贴近手机背面 NFC 感应区保持不动；
5. 读取成功后自动继续加载；中途移开、贴错卡等会给出提示，可直接重新贴靠或点「重试」。

**错误提示对照**：

| 提示 | 原因 | 处理 |
|---|---|---|
| 此设备不支持 NFC / NFC 未开启 | 设备无 NFC 或开关关闭 | 更换设备或在系统设置开启 NFC |
| 未识别到 YubiKey | 读到的卡片非 ISO-DEP（如银行卡） | 换用 YubiKey 贴卡 |
| YubiKey 拒绝了请求，请检查挑战槽位配置 | SELECT 被拒（应用未找到/安全状态不满足） | 确认 YubiKey 已配置 HMAC 槽位，且槽位选择与 KeePassXC 一致 |
| 挑战-应答失败，请保持贴合直至完成 | HMAC 指令被拒或通信中断 | 保持贴合重试；多次失败检查槽位 |
| KDBX 3 数据库不支持挑战-应答解锁 | 数据库为 KDBX 3 | 在 KeePassXC 中升级为 KDBX 4 |

> 说明：挑战-应答采用两阶段流程——先解析数据库头提取挑战值，再经 YubiKey NFC 计算 HMAC-SHA1 应答后加载。YubiKey 实体卡互操作为**待验证**状态（未做真机 E2E），首次使用请先在非关键库上验证。

> **保存限制**：挑战-应答（XC）数据库暂不支持在手机端保存修改（编辑后保存会明确提示"暂不支持保存，您的修改未保存"）。原因：KDBX 保存时会重新生成内部挑战值，需重新贴卡计算新应答才能落盘，该「保存前重贴卡」流程将在后续版本支持。解锁、浏览、从远端刷新均不受影响；如需修改请在 KeePassXC 桌面端操作。

## 快速解锁与锁屏

- 应用内锁屏（超时/手动锁定）弹出快速解锁页：库仍保持解密状态在内存中，输入快速解锁密码或通过生物识别即可恢复，无需重新输入 OTP 码/贴卡；
- 应用进程被结束后的冷启动，会进入完整解锁流程，OTP 码 / YubiKey 贴卡等硬件因子需要重新完成。

## 安全说明

- OTP secret、YubiKey 应答**不持久化**：每次解锁重新派生/采集；
- 最近记录仅保存主密码分量（且仅在开启生物识别时加密保存，有效期 90 天）；
- 挑战槽位、辅助文件位置、密钥文件位置等非敏感配置会记忆在最近记录中。
