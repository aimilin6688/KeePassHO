# 快速填充方案设计：剪贴板增强 + 解锁会话通知

> 状态：**已实现并真机验证**（2026-10-03）
> 关联调研：《弹框与窗口拖拽能力调研报告》自动填充调研结论（2026-10）
> 目标：在 HarmonyOS 系统未开放三方"填充提供方"API 的前提下，为 KeePassHO 提供最接近系统密码保险箱体验的快速填充能力
> 实现过程经历 6 轮真机迭代（详见第 10 节实施记录），本文档为最终态

## 1. 背景与调研结论

### 1.1 系统能力结论

| 通道 | 结论 | 依据 |
| --- | --- | --- |
| 系统密码保险箱（Password Vault） | ❌ 无三方 provider 扩展点 | 密码自动填充服务基于关键资产存储，系统封闭管理 |
| `autoFillManager`（API 11+/26） | ❌ 消费方 API | 仅表单所在应用可调用 `requestAutoFill/requestAutoSave` |
| 无障碍服务注入文本 | ❌ 不可行 | `injectGesture/performAction/getFocusElement` 等核心接口 API 10~12 已全部废弃 |
| 实况窗 Live View | ❌ 场景不符 | 准入场景限出行/配送/运动/导航等，需 AGC 权益申请 |
| 悬浮窗 | ❌ 权限受限 | `SYSTEM_FLOAT_WINDOW` 需 AGC 特批，且最终仍依赖剪贴板 |
| 输入法（IME Kit） | ⚠️ 可行但重 | 自研键盘体验无法匹敌系统键盘，暂缓 |
| **剪贴板 + 通知快捷操作** | ✅ **本方案** | 写剪贴板零权限；通知 `actionButtons` 支持独立 wantAgent、`SEND_COMMON_EVENT` 后台复制 |

### 1.2 智能填充联动

系统智能填充服务推荐优先级为 **剪贴板 > 历史表单 > 华为账号 > 联系人**。已接入智能填充的目标 App 中，点击输入框会自动弹出剪贴板填充建议——本方案的复制动作直接借力，等效"准自动填充"。

## 2. 方案总览

```
方案一（地基）：ClipboardUtils 增强
  InApp 范围管控 + 清除补偿 + 静默复制 + 清理任务同步重置
        ↓ 被复用
方案二（核心）：解锁会话通知
  SessionManager（会话/窗口双生命周期 + 后台保活）
  + SessionNotificationService（常驻通知 + 动态按钮 + 实时标题 + 倒计时刷新）
  + CopyEventService（公共事件订阅 → 后台复制）
```

用户旅程：

```
解锁 DB → 通知栏出现常驻通知（标题=条目名，按钮按条目字段动态显示）
  → 切到任意 App → 下拉通知栏（点卡片展开按钮）→ 点[复制账号]/[复制密码]
  → 后台完成复制（不离开当前 App）→ 长按输入框粘贴
  → 30s（复用剪贴板清理设置）后：剪贴板自动清除 + 通知自动消失
  → 切换条目/再次复制 → 窗口与清理计时同步重新计算
  → 锁库/关库 → 通知、剪贴板、会话状态全部清理
```

## 4. 方案一：剪贴板增强（地基）

### 4.1 增强 vs 现状

| # | 原问题 | 增强设计 |
| --- | --- | --- |
| 1 | 写入未设置 `shareOption`，默认允许跨设备剪贴板同步 | `PasteDataProperty.shareOption = ShareOption.INAPP`，禁止经华为账号流转到其他设备 |
| 2 | 清除依赖 `setTimeout`，后台冻结后定时器停摆，密码可能长期残留 | 清除任务记录 `expireAt` 时间戳；`onForeground` 补偿扫描（`flushPendingClears`）；锁库/关库强制清除（`forceClearNow`） |
| 3 | `copy()` 成功固定 toast，后台复制时无法显示 | `copy/copyAutoClear` 增加 `silent` 可选参数，后台静默路径仅 hilog |
| 4 | 剪贴板清理与通知窗口各自计时不同步 | 新增 `restartAutoClear()`：存在未执行任务时随通知窗口重置重新计算（无任务时不动用户剪贴板） |

### 4.2 最终 API

```
ClipboardUtils
├── copyAutoClear(text, silent?)          // 读设置后调 copy（向后兼容，现有调用方零改动）
├── copy(text, timeoutClear?, silent?)    // silent=true 跳过 toast（供后台复制）
├── clear(timeout?)                       // 兼容保留
├── scheduleClear(timeoutSec)             // 私有：任务记录 expireAt，队首起 setTimeout
├── flushPendingClears()                  // onForeground 补偿：冻结期间到期未清的立即清
├── restartAutoClear()                    // 通知窗口重启时同步重置清理计时（无任务则 no-op）
├── forceClearNow()                       // 锁库/关库：清队列 + 立即 clearData
└── writeData 内 shareOption=INAPP        // 禁止跨设备同步
```

## 5. 方案二：解锁会话通知（核心，最终态）

### 5.1 双生命周期模型（实现中确立的关键设计）

| 生命周期 | 范围 | 结束条件 |
| --- | --- | --- |
| **会话**（Session） | 数据库解锁期间始终存活 | 仅锁库/关库（`end()`） |
| **通知窗口**（Window） | 时长 = 剪贴板清理设置（默认 30s，-1 永不清除） | 到期仅取消通知（`expireWindow()`），**会话保持** |

**窗口重启触发点**（三处统一走 `restartWindow()`，通知窗口与剪贴板清理计时**同步重置**）：
1. 解锁成功（`start()`）
2. 切换条目（`setActiveEntry`，同时结束复制态文案）
3. 复制成功（`onCopied(fieldType)`，剪贴板有新内容）

**窗口到期**：`expireWindow()` 取消通知 + 停倒计时 + 释放后台保活，但会话保持——再次切换条目或复制时通知自动复活（迭代 #4 修复的行为）。

### 5.2 组件职责

#### SessionManager（`services/SessionManager.ets`）

- **事件 hook**：`EVENT_LOCK_ACTION`（`'unlock'`→start，其余→end）+ `EVENT_LOCK_SCREEN`（手动锁/自动锁→end）
- **条目绑定**：`setActiveEntry(groupId, entryId, title, hasUsername, hasPassword)`——由 EntryView 打开条目详情时调用；**仅当条目含账号或密码时才调用**（无凭据条目/分组类条目不更新通知，由调用方守卫）
- **倒计时 ticker**：`startTicker()` 每 `COUNTDOWN_TICK_MS`(5s) 检查窗口剩余时间——剩余 >0 且处于复制态则重发同 ID 通知刷新"N秒后自动清除"文案；剩余 ≤0 → `expireWindow()`
- **后台保活**：`onAppBackground()` 会话进行中申请短时任务（`backgroundTaskManager.requestSuspendDelay`，实测 3 分钟）；`onAppForeground()`/`expireWindow()`/`end()` 释放
- **状态广播**：`AppStorage('sessionActive')`

#### SessionNotificationService（`services/SessionNotificationService.ets`）

- **授权**：`ensurePermission()`——`isNotificationEnabled` + 首次 `requestEnableNotification`；拒绝即静默降级
- **开关统一拦截**：`publishActiveEntry/publishCopied` 入口校验 `isNotifyEnabled()`——开关关闭后所有发布路径（解锁/切条目/复制）均不发
- **通知构建**（`buildRequest`）：
  - `id = SESSION_NOTIFY_ID`（同 ID 重发即更新，实测更新不收起已展开的按钮）
  - `isOngoing: true`、`tapDismissed: false`（点击按钮后通知保留）
  - `autoDeletedTime = 窗口起点 + remainingSec×1000`（永不清除模式不设置）；进程冻结/死亡时由系统兜底清除
  - `wantAgent`（点主体拉起应用）+ `removalWantAgent`（划掉通知→`SESSION_ACTION_NOTIFY_REMOVED` 公共事件，仅支持 SEND_COMMON_EVENT）
  - **动态按钮**：条目含账号→"复制账号"按钮；含密码→"复制密码"按钮；两者都有→双按钮；未绑定条目→无按钮
  - **wantAgent 缓存**：按 `groupId|entryId|hasUsername|hasPassword` 缓存，倒计时刷新免重建（每次发布仅一次 publish 调用）
- **文案**（标题实时跟随条目）：
  - 标题 = 绑定条目名称（实时更新）；未绑定或条目无标题时回退"快速填充"
  - 正文（与动态按钮联动）：双字段→"点按钮可快速复制账号或密码"；仅账号→"点按钮可快速复制账号"；仅密码→"点按钮可快速复制密码"；未绑定→"解锁会话进行中"
  - 复制态：标题仍为条目名，正文"已复制{账号|密码}，N秒后自动清除"（N 为窗口剩余秒数，5 秒粒度刷新；永不清除模式为"已复制{账号|密码}"无秒数）
  - **严禁任何凭据明文进入通知/日志**
- **取消**：`cancelSession()`——锁库/关库/窗口到期/用户划掉/开关禁用

#### CopyEventService（`services/CopyEventService.ets`）

- **订阅**：`createSubscriber + subscribe`（动态订阅，免权限声明），事件 `SESSION_ACTION_COPY_FIELD` / `SESSION_ACTION_NOTIFY_REMOVED`
- **复制链路**：解析参数（`parameters['groupId'|'entryId'|'fieldType']` 严格 typeof 校验）→ 会话校验 → `KdbxUtils.getEntry` → `getFieldValueString`（用户名/密码，空值静默失败）→ `resolveFieldRefsInText`（字段引用解析，与页面复制一致）→ `ClipboardUtils.copyAutoClear(text, silent=true)` → `SessionManager.onCopied(fieldType)`（重置窗口+清理计时）→ `publishCopied` 更新文案
- **划掉通知**：`SESSION_ACTION_NOTIFY_REMOVED` → `onNotificationRemoved()`——仅结束通知窗口状态，**不锁库、不清剪贴板**

### 5.3 生命周期时序

| 时机 | 动作 |
| --- | --- |
| 解锁 DB（冷启动 Password 页 / 锁屏重解锁 UnLockDatabase 页） | 两路径统一发 `EVENT_LOCK_ACTION='unlock'`（**实现迭代 #3 修复**：Password.handleSuccessMessage 原缺失事件）→ start → 窗口重启 + 发布通知 |
| 打开条目详情（EntryView，所有详情路径必经） | 凭据守卫 → setActiveEntry → 窗口重启 + 标题/按钮实时更新 |
| 通知按钮点击（任意 App 内） | 公共事件 → 后台复制 → 通知文案更新为复制态 |
| 点击通知主体 | wantAgent 拉起应用（首次点击先展开按钮，系统行为） |
| 用户划掉通知 | removalWantAgent → 结束通知窗口状态，不锁库 |
| 锁库（手动/自动）/ 关库 | end → 取消通知 + 释放保活 + `ClipboardUtils.forceClearNow()`（锁库即净） |
| 通知窗口到期 | expireWindow → 取消通知 + 释放保活，会话保持 |
| 应用切后台（会话进行中） | 申请短时任务保活（见 5.4） |
| 应用回前台 | `flushPendingClears()` 剪贴板补偿 + 释放保活 |
| 应用 onDestroy | unsubscribe + cancel + end |

### 5.4 后台保活（迭代 #5 确立）

**根因**：应用切后台约 20 秒后被系统**冻结**——JS 定时器全部停摆（清理/倒计时停止）且动态公共事件不再投递（通知按钮无响应）。

**修复**：会话进行中切后台 → `backgroundTaskManager.requestSuspendDelay`（实测授权 180s，覆盖 30s 窗口期）→ 定时器与事件投递全程正常；回前台/窗口到期/锁库时 `cancelSuspendDelay` 释放。

**残余限制**（平台约束，与 iOS/Android 密码管理器一致）：保活上限 3 分钟——窗口期（≤30s）内无感知；通知本身由 `autoDeletedTime` 系统级兜底清除，不受冻结影响。

### 5.5 安全设计

1. **明文隔离**：公共事件参数仅含 `groupId/entryId/fieldType`；明文仅在复制调用栈内瞬时存在
2. **通知内容**：标题为条目名、正文为操作提示，永不包含凭据明文；hilog 复制链路无明文
3. **跨设备泄露**：`ShareOption.INAPP` 阻断分布式剪贴板同步
4. **事件伪造面**：三方可订阅同名事件，最多获得 entryId（不敏感）；写剪贴板由本应用进程完成
5. **锁库即净**：通知、剪贴板、会话状态、后台保活四线同步清理
6. **开关即时生效**：禁用→立即删除已显示通知（含永不清除窗口的无兜底残留）；启用→会话进行中立即恢复（迭代 #6 修复：新值显式传参避免 put 异步落盘回读旧值导致行为颠倒）
